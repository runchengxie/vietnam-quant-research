# 推荐数据栈与分阶段落地路线

> 更新时间：2026-08-27  
> 目标：先以低成本建立可信的研究数据，再根据策略真正需要的字段升级数据源。

## 推荐起点

首选组合是：

```text
vnstock Community/Sponsor
        + SSI FastConnect（申请测试）
        + VSDC 公开数据
```

三者职责不同：

- **vnstock**：快速覆盖股票池、日线和基础字段，适合 notebook、因子原型和批量研究；
- **SSI FastConnect**：提供券商 API 形式的证券列表、指数、OHLCV、盘中/实时能力，可用来交叉核验和探索自动化接口；
- **VSDC**：补充外资持股上限、foreign room、证券状态、注销和转板等行情 API 不一定提供的字段。

第一阶段不要同时购买所有商业数据。先回答两个问题：

1. 全市场日频数据是否能够稳定获取和清洗？
2. 经过交易成本、停牌和流动性约束后，是否存在值得继续研究的信号？

## 分阶段选择

| 阶段 | 预算量级 | 数据组合 | 研究目标 | 进入下一阶段的条件 |
|---|---:|---|---|---|

| 1 研究 | 约 ¥0–1,500/年 | 加入已确认价格的 vnstock Sponsor；申请 SSI FastConnect | 批量刷新、日频因子、盘中可行性和双源抽样校验 | 需要 point-in-time 财务、公司行动或标准行业字段 |
| 2 标准化基本面 | 约 ¥2,300–2,800/月起 | FiinPro-X 试用/订阅 + vnstock/SSI/VSDC 校验 | 财报、估值、所有权、公司行动、筛选和历史研究 | 策略明确依赖盘口、Tick、Level 2 或正式许可 |

## 数据流

建议的数据流不是“抓完直接回测”，而是保留原始证据：

```text
source adapters
      ↓
raw snapshots + request metadata
      ↓
normalized tables
      ↓
quality checks + reconciliation
      ↓
factors / backtest / reports
```

每个原始快照至少记录：

```text
source
source_url_or_endpoint
retrieved_at_utc
market_timezone
request_parameters
response_status
raw_payload_or_file_hash
parser_version
schema_version
```

这样当供应商改字段、网页结构或修订历史数据时，能够回答“某个回测结果当时使用了哪一版数据”。

## 第一批建议表

### `instrument_master`

记录 ticker、证券名称、ISIN、市场、证券类型、上市/登记日期、转板、退市、停牌和当前状态。关键是使用有效期字段，例如 `valid_from`、`valid_to` 和 `status`，而不是只保存当前股票列表。

### `price_daily`

保留交易日、ticker、市场、raw OHLC、成交量、成交额、成交笔数（如有）、复权字段、来源和抓取时间。原始价格不得被复权价格覆盖。

### `price_intraday`

保留时间戳、时间粒度、OHLC、成交量、成交额、交易状态和来源。统一转换到 `Asia/Ho_Chi_Minh` 交易日，同时保留供应商原始时间戳和 UTC 时间。

### `fundamentals`

不要只有“2025 年年报”这一列。至少要有报告期、公告时间、可用时间、财报类型、币种、合并/单体标识、来源和修订版本，保证回测按信息可得时间使用数据。

### `corporate_actions`

记录现金分红、拆分、配股、增发、除权日、登记日、公告日、比例、每股金额和来源。公司行动要能驱动复权因子，同时保留事件原貌。

### `foreign_ownership`

记录外资持股上限、已持股数量、剩余可买数量、观察日期、有效时间、证券状态和来源。不要把每日 room 当成价格行情的静态属性。

### `index_membership`

记录指数、成分股、生效日期、移除日期、公告日期和来源。历史指数研究不能用今天的成分股列表回填过去。

### `source_observations`

集中记录来源、请求、响应、抓取时间、解析版本、质量状态、错误信息和人工复核结果。这张表既是调度审计，也可作为后续供应商比较的证据表。

## 最小建库路线

### 第一步：建立 security master

先合并 HOSE、HNX、UPCoM 和衍生品的代码列表，明确 ticker、市场、证券类型和生效日期。对同一公司不同证券、转板前后代码和已注销证券使用事件记录，不直接删除历史记录。

### 第二步：拉取全市场日线

先选一段能覆盖多个市场状态的历史区间，使用 vnstock 或 SSI 拉取日线，保存原始响应。对股票数量、交易日数量、缺失率、价格为零、成交量异常、涨跌停和极端跳变做自动统计。

### 第三步：双源抽样校验

每个市场随机抽取大盘股、中盘股、小盘股、长期停牌股和近期转板/退市股，比较：

- 交易日是否一致；
- OHLC 是否一致；
- 成交量/成交额单位是否一致；
- 复权价是否混入 raw 字段；
- 缺失、停牌和涨跌停是否被错误填充。

### 第四步：加入事件和外资字段

用 VSDC、交易所披露和供应商公司行动补齐 room、转板、注销、分红、拆分和配股，并给每个事件增加公告日期和可用日期。此时才开始构建复权价格和可交易股票池。

### 第五步：跑基础研究

优先做数据需求较低且容易审计的信号：

- 动量与反转；
- 流动性、换手率和成交额；
- 波动率与涨跌停行为；
- 市值/规模；
- 外资流和 foreign room；
- 指数纳入/剔除效应。

每个结果都要包含交易成本、停牌处理、流动性过滤和样本外区间。

### 第六步：按瓶颈升级

- 财报字段和公司行动是主要瓶颈：先评估 FiinPro-X，而不是继续堆行情 API；
- 盘中信号是主要瓶颈：先确认 SSI 盘中历史长度和可用性；
- Tick/盘口和执行是主要瓶颈：向 HOSE/HNX/ICE 询问 Feed、历史深度和许可；
- 只是下载速度慢：先做缓存、增量更新和并发控制，不要立刻购买机构 Feed。

## 选型原则

### 研究库和生产库分开

研究库可以由 notebook 临时调用 vnstock；生产库必须有定时任务、重试、缓存、原始快照、监控和审计记录。两者使用同一套标准化字段，但不能共享未审计的临时文件。

### 原始、标准化、派生三层分开

```text
raw       = 供应商原样数据和请求证据
normalized = 统一字段、单位、时间、ticker 和状态
derived   = 复权价格、因子、信号、回测结果
```

任何派生字段都应该能追溯到 normalized 字段和具体 source observation。

### 用第二来源做校验，不一定用第二来源做主库

第二来源的主要价值是发现缺失、字段口径和极端值问题。可以让一个来源承担主抓取，再用另一个来源做抽样或关键日期校验，避免为“看起来更专业”而重复支付完整订阅费。
